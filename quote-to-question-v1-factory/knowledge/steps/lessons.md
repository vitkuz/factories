# Lessons store

A flat Markdown list of lessons that change what the next run does. One line per lesson: what went wrong, then what to do instead. The file lives beside the other knowledge files of this factory and is loaded into the steps that generate, judge and compact questions.

Writing rules:
1. Append only, at the end, under the existing header. Never edit or delete a line.
2. One line per lesson, general enough to apply to any quote. Name no quote, author, run folder or step number.
3. Read the existing lines first and compare by meaning; skip a near-duplicate.
4. Keep only lessons the files prove and a future run can act on. Compare the steps against each other: a flag in the semantic core that the quote's own words contradict; a judge verdict that contradicts a flag (a "Почему" judged direct with why and reason both false, or the reverse); a question that lost its "ли" or became a statement with "?" between generation and compaction; a score written as a string, a missing field, a list that came back empty; the same question generated by both branches; a history question kept although the research found nothing. Drop one-off trivia.
5. Never turn a judge's taste into a rule: "this kind of question keeps getting judged weak" is an observation about the judges, not a lesson for the generator. A lesson names what a step did against its own rules, not what the judges disliked.
6. No lessons from a clean run: a run whose files show nothing new adds nothing.

Reading rules: the lessons are prior evidence from past runs, not law. Apply them when the situation matches; the knowledge rules of the step still win.
