# How web research is done and how a findings file is shaped

One findings file per sub-question, named after the sub-question's number and slug from the
issue tree. The file is written for the writer who will turn it into a report without
re-reading the sources, and for the reviewer who will check that every claim is backed.

## How to search

- Run every query the issue tree gives for the sub-question. Add your own when the first
  results are thin, and record the added queries so the reviewer can see what was tried.
- Open the source, do not trust the snippet. A snippet summarises; the page carries the
  number, the date and the caveat.
- Read at least three independent sources per sub-question. Two pages that quote the same
  press release are one source.
- Look for the opposite claim on purpose. Search for "<claim> criticism", "<claim> wrong",
  "<claim> debunked" or the equivalent in the source language. A sub-question with no
  disagreement recorded either has a settled answer or was not searched hard enough; say
  which.
- Prefer sources in this order: primary data (filings, statutes, datasets, official
  statistics), institutional or peer-reviewed studies, named-outlet reporting, an expert's
  own words, secondary summaries. Say the source type next to every finding.
- Note the date of every source. A figure from 2019 is a 2019 figure and is labelled so.

## Sections of a findings file, in this order

1. **Sub-question** — copied from the issue tree, with its number and slug.
2. **Hypothesis under test** — copied from the issue tree.
3. **Findings** — numbered `F1`, `F2`, … Each is:
   - one sentence stating the fact, with the number, the unit and the date it refers to,
   - the source: title, outlet or author, URL, date published, date read, source type,
   - one line on how far to trust it and why (sample size, who paid for it, how old).
   Eight to fifteen findings is usual. Fewer is fine if the sources are strong; more means
   the sub-question was too broad or the analyst did not stop at the eighty percent.
4. **Disagreement** — where sources conflict: which findings, what each says, and which the
   analyst would lean on and why. "None found" is a valid entry when the searches for the
   opposite claim are listed.
5. **Verdict on the hypothesis** — one line: held, failed, or partly held, and the finding
   numbers that decide it.
6. **Gaps** — what the sub-question needed that no source gave, one line each. Empty is
   allowed; missing is not.
7. **Queries run** — every query, one per line, marked with the search engine or tool and
   whether it returned anything used.

## Rules

- No finding without a URL. A fact you remember but cannot source is not a finding; it may
  go under gaps as "believed but unverified".
- Quote numbers as the source gives them. Convert units in a second sentence, never
  silently.
- Never paste long passages. A finding is one sentence; a quotation is at most two lines
  and is marked as a quotation.
- On a second pass, when a review lists evidence gaps, change only the files those gaps
  concern, add the new findings with the next free numbers, and add a line at the top of
  the file saying which gap the pass filled.
