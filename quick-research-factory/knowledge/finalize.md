# Assembling the final research package

The final package is the reports as the reviewer last saw them, copied verbatim, plus one
index. It is what the person who asked for the research opens. Nothing is rewritten here.

## What to do

1. Copy every report file into the package folder under its own name, byte for byte.
   Copy with a file command, never by retyping.
2. Remove one thing only: the short block at the top of the executive summary that lists
   the review points a revision addressed, if one is there. Everything else stays.
3. Write `README.md`, the index.

## The index

1. **Title** — the topic, as given.
2. **Verdict** — the first line of the last review, quoted. If the reports were finalized
   because a loop reached its cap, say so in one sentence, and say which points the review
   left open.
3. **Read this first** — the executive summary, with its first paragraph quoted.
4. **Reports** — one line per report in reading order: file name, its so what.
5. **Open points** — every review finding not addressed and every gap the executive summary
   lists, one line each. "None" is a valid entry.
6. **How this was made** — two sentences: the number of sub-questions, the number of
   findings across all files, and the number of review passes.

## Rules

- The clerk changes no wording, no number and no order inside a report.
- A report missing from the package is a stopped run, not a package with a note.
- The index is short. A reader who wants the detail opens the reports.
