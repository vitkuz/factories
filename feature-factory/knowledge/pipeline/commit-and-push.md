# Commit and push

The last step of a run. It commits and pushes **this feature's changes only**, repo by repo, and
then the project. Other sessions may be working in the same repos at the same time, so you add your
changes on top of theirs and never move their work.

## What belongs to this feature

- The files listed in this run's change reports (`*/changes.md`, `*/fix.md`, the docs and context
  updates), in `repos/back`, `repos/front`, `repos/tools`, `repos/docs` and `docs/context/`.
- In the project: the feature's folder under `features/` if it has one, this run's folder under
  `run/`, and the factory's data under `factories-data/` (the lessons log this run appended to).
- A file that is changed but not in any report belongs to someone else. Leave it alone, and list it
  in your output.

## Order

1. **Each repo under `repos/` that is a git submodule** (`git -C repos/<name> rev-parse --show-superproject-working-tree`
   prints the project): stage only this feature's paths with `git add <path> …`, commit, push. Skip a
   repo with no changes from this feature.
2. **A `repos/<name>` that is a plain folder** (not a submodule): its files are committed with the project in step 3.
3. **The project**: stage the moved submodule pointers (`git add repos/<name>`), this feature's
   `docs/context/` files, its `features/` folder, this run's `run/` folder and `factories-data/`;
   commit, push.

## Rules

- Stage by explicit path. Never `git add -A`, `git add .` or `git commit -a`.
- Never stash or shelve: no `git stash`, no `--autostash`, no temporary commits of anything that
  isn't this feature's, no copying files aside.
- Never `push --force`, `reset --hard`, `checkout --`/`restore` on files you didn't change.
- Push rejected because the remote moved: `git pull --rebase` if the working tree has no
  uncommitted changes, then push again. If other people's uncommitted changes block the rebase, or a
  conflict needs a judgement call: stop, push nothing more, and return FAILED, naming the repo and
  what is blocking it.
- Push from the current branch to its upstream. If a remote over HTTPS refuses access, retry the
  same push with the SSH address of the same repo (`git push git@<host>:<owner>/<repo>.git <branch>`,
  using the host alias from `~/.ssh/config` that the project's other remotes use). Do not change the
  remote setting.
- Commit message: one plain line saying what the feature did in that repo (`Add company edit page`).
  In the project: `Feature <feature>: bump repos, context docs, run`. No attribution or
  "generated by" lines, no Co-Authored-By.
- Before you commit, look at the staged diff (`git diff --cached --stat`). Never commit `.env`
  files, credentials, keys or tokens; if one is staged, unstage it and say so.

## Output

Per repo: committed (short sha and message), pushed (yes/no), or skipped and why. Then the changed
files you left alone, and anything that failed.
