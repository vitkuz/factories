# Run report

Written for the user, who will read it once. Plain language, short sentences.

1. **Outcome** — one line: done, partly done, or stopped, and why.
2. **What was built** — per repo, the files changed and what they do now.
3. **Spec changes** — which `docs/context/` files changed.
4. **Deployed** — stacks and what changed in each; the front URL. Say plainly if nothing was deployed.
5. **Tested** — what the API tests and the browser test proved, with pass/fail counts. Say plainly what was not tested.
6. **Open issues** — anything failing, skipped or left for later.
7. **How to try it** — the URL and the clicks, or the `curl`.

Never include passwords, tokens or API keys.
